# CSS and HTML

HTML describes the structure and meaning of web content. Elements are written with tags, often as an opening and closing pair around content. Attributes provide additional information, such as a link's destination in `href` or an image's alternative text in `alt`. Semantic elements such as `header`, `nav`, `main`, `article`, `section`, and `footer` communicate the role of page regions more clearly than using generic containers for everything. Headings should follow a logical hierarchy, and interactive controls should use native elements such as buttons and links whenever possible.

An HTML document has a document type declaration and a root `html` element. The `head` contains metadata, the page title, and references to stylesheets or scripts; the `body` contains visible content. Use a viewport meta tag for layouts that adapt to mobile screens. Form controls need associated labels so people can understand their purpose, including users of assistive technology. Images that convey information need concise alternative text; decorative images can use empty alternative text so they are not announced unnecessarily. Clear document structure improves accessibility, maintainability, and search engine interpretation.

CSS controls presentation. A rule consists of a selector and declarations inside braces. A declaration pairs a property with a value, such as `color: navy`. Selectors can target elements, classes, IDs, attributes, and relationships. Classes are usually preferable for reusable styling because IDs are intended to be unique and have high specificity. The cascade determines which declarations apply based on origin, importance, specificity, and source order. When styling behaves unexpectedly, inspect the cascade rather than adding increasingly specific selectors. Custom properties such as `--brand-color` can centralize repeated design values.

The box model describes each element's content, padding, border, and margin. With `box-sizing: border-box`, declared widths include padding and border, which often makes layout easier to reason about. Modern layouts usually use Flexbox for arranging items along one dimension and Grid for two-dimensional arrangements. Relative units such as percentages, `rem`, and viewport units can help create adaptable designs. Media queries apply styles based on conditions such as viewport width. Responsive design should preserve content and usability across screen sizes, not merely shrink a desktop layout.

Accessibility is part of front-end correctness. Text and controls need sufficient contrast; keyboard users must be able to reach and operate interactive elements; focus indicators should remain visible. Do not remove native focus outlines without providing a clear replacement. Avoid using color as the only signal for errors or status. Respect reduced-motion preferences for nonessential animation. Test with keyboard navigation and varied viewport sizes, and include accessible names for controls whose visible labels are not obvious.

Keep HTML, CSS, and behavior understandable. Use semantic markup and reusable classes instead of brittle selectors tied to deep document structure. Prefer external stylesheets for shared site styling and keep style rules grouped by component or purpose. Avoid inline styles as the default, though they can be appropriate for computed values. Validate that links and form controls have useful behavior, not just appearance. Browser developer tools can inspect computed styles, layout boxes, and accessibility information. A simple, consistent design system of spacing, colors, typography, and components makes pages easier to extend than unrelated one-off values.
