# Advanced Python

Python's object model explains many behaviors that can seem surprising at first. Variables are references to objects, and assignment binds another name to the same object. A shallow copy duplicates only the outer container, so nested mutable values remain shared; a deep copy recursively copies nested values when that is actually appropriate. Equality (`==`) tests whether values compare equal, while identity (`is`) tests whether two references point to the same object. Use `is` for singleton checks such as `value is None`, not for comparing ordinary strings or numbers.

Classes define custom object types. An instance stores state, while methods describe operations on that state. `__init__` initializes a newly created instance, and special methods such as `__repr__`, `__iter__`, and `__eq__` let an object work naturally with built-in operations. Inheritance can share or specialize behavior, but composition is often easier to understand: one object holds and uses another instead of relying on a deep class hierarchy. Properties provide attribute-style access when validation or computed values are useful. Dataclasses reduce repetitive boilerplate for classes primarily used to store data. Type annotations document expected inputs and outputs and enable static tools to find some inconsistencies; Python generally does not enforce annotations at runtime.

Iterators produce values one at a time. An iterable can be passed to `iter`, and an iterator's `__next__` method yields the next value or raises `StopIteration`. Generator functions use `yield` to create iterators lazily, which can process large or unbounded sequences without holding every result in memory. Comprehensions provide a concise way to build collections, but should remain readable rather than nesting many conditions and loops. Generator expressions are useful when a consumer can process one item at a time. Lazy evaluation can reduce memory use, but it also means computation or exceptions may occur later than the line where a generator is created.

Decorators wrap or transform functions or classes. The `@decorator` syntax is a convenient form of reassignment that passes the decorated object to a callable. A wrapper should normally use `functools.wraps` to preserve metadata such as the original function's name and documentation. Context managers define setup and cleanup behavior around a `with` block; they are especially valuable for files, locks, and transactions. The `contextlib` module provides helpers for simpler context managers. Cleanup belongs in a `finally` block or a context manager rather than after a sequence of operations that might fail.

Exceptions should describe failures clearly and be handled at the layer that can make a useful decision. When translating one exception into a domain-specific exception, use exception chaining with `raise NewError(...) from original_error` to retain diagnostic context. Avoid using exceptions for ordinary control flow when a direct condition is clearer. Logging is different from printing: the `logging` module supports severity levels, timestamps, and configurable destinations, allowing applications to control diagnostic detail without changing business logic.

Concurrency has several models. Threads are convenient for overlapping I/O, but CPython's Global Interpreter Lock usually limits simultaneous execution of Python bytecode for CPU-heavy work. Processes can use multiple CPU cores at the cost of process startup and data transfer. `asyncio` uses cooperative concurrency: `async def` defines a coroutine, `await` yields control while waiting, and an event loop schedules other ready coroutines. Async code helps with many concurrent network operations only when the libraries it calls are also asynchronous. Do not block the event loop with slow synchronous work. Choose the simplest model that suits the workload, protect shared mutable state, and measure before optimizing.
